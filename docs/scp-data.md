# Local data: `data/`

`data/` is the local archive produced and used by the application. It
contains source data, HTML prepared for the reader, a navigation index, and
optionally downloaded images.

```text
data/
├── index.json
├── update.log
├── json/
│   ├── content_series-1.json
│   ├── content_joke.json
│   └── content_scp-001.json
├── html/
│   ├── series-1/
│   │   └── scp-173.html
│   ├── international/
│   └── ...
└── images/
    └── ...
```

## `json/`: article sources

The API JSON files are stored here, separated by series or group. Filenames
follow the manifest, for example `content_series-1.json` or
`content_international.json`. Their keys are article identifiers, and their
values preserve the source fields, including HTML and original markup when
available.

`content_scp-001.json` is the exception: the loader builds it from the
SCP-001 index page and its linked proposals instead of downloading it from
the API manifest.

## `html/`: reader-ready copy

The loader generates one HTML file per article, organized into subfolders by
group (`series-1`, `joke`, `international`, etc.). Unlike the source JSON,
this content may include local transformations:

- replaces references to articles available in the archive with relative
  local links;
- keeps references that are not in the archive as external links;
- removes the repeated license box;
- uses local image copies when run with `--media`.

The reader checks this HTML first. If it is missing, it can fall back to
`raw_content` or `raw_source` in the JSON file.

## `index.json`: generated index

This is a JSON object whose keys are the records' `link` paths/values, which
are not necessarily their SCP identifiers. Each value contains the data the
reader needs to locate and display the article:

| Field | Use |
|---|---|
| `link` | Source identity/path; also the index key. |
| `url` | Canonical Wikidot URL. |
| `scp_id` | Identifier accepted by the reader, such as `SCP-173`. |
| `title` | Display title. |
| `folder` | Subfolder of `html/` containing the article. |
| `json_file` | Source file in `json/`, used as a fallback if the HTML is missing. |
| `html_file` | Generated HTML filename. |
| `json_key` | May appear when the JSON record's internal key differs from `scp_id`. |

This file is generated by the loader; it is not the API's remote index.

## `images/`: optional media

This folder is populated when an update runs with `--media` or when
`update --media` is selected in the reader. Images are not downloaded by
default. Local HTML may still reference remote images when local copies do not
exist.

## `update.log`

The reader writes the update process output here. It is overwritten when a
new update is started from the interface.

## Reading and update flow

1. At startup, the reader opens `index.json`. If it does not exist, it starts
   an update.
2. To open an article, the reader resolves its identifier through the index
   and loads `html/<folder>/<html_file>`.
3. If that HTML file is missing, it looks up the corresponding record in the
   JSON file specified by `json_file`.
4. During an update, the loader refreshes source data, reprocesses what is
   needed, and regenerates the index. Images are downloaded only when
   explicitly requested.

Files in this folder are generated data and may change with every update;
they should not be confused with source code or an immutable API schema.
